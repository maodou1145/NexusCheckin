# 取件码绑定 · 部署与使用

> **一句话**：用户在浏览器把 Token 投递到「信箱」，拿到 **4 位取件码**；
> 手表「我的 → 取件码绑定」输入这 4 位数字即可完成绑定。
> 取件码 **10 分钟有效、只能取一次、取走即刻销毁**。

---

## 一、部署（作者一次性操作，约 20 分钟）

### 1. 注册 uniCloud 并创建服务空间

1. 打开 https://unicloud.dcloud.net.cn/ 用 DCloud 账号登录（没有就注册）
2. 创建一个**服务空间**（免费版即可，选阿里云或腾讯云都行）

### 2. 创建云函数 `nxbox`

1. 进入服务空间 → 左侧【云函数】→ **新建云函数**
2. 云函数名称填 **`nxbox`**
3. 把仓库里 `tools/box-server/index.js` 的内容**整段粘贴**进云函数的 `index.js`
4. `tools/box-server/package.json` 的内容粘进云函数的 `package.json`（无第三方依赖）
5. 保存 → 上传部署

### 3. 创建数据库集合

【云数据库】→ 新建集合，名字填 **`nx_box`**
（阿里云即使不建、首次写入也会自动创建，但建议手动建，权限选「仅创建者可读写」即可——
本云函数用管理端权限访问，不受影响）

### 4. 配置云函数 URL 化

1. 【云函数】→ 找到 `nxbox` → **详情** → 配置**访问路径**：`/nxbox`
2. 保存后得到访问地址，形如：
   `https://xxx-xxxxxxxx-xxxxxx.bspapp.com/nxbox`
3. 自测一下（把域名换成你的）：
   ```bash
   curl -X POST "https://你的域名/nxbox/put" -H "content-type: application/json" -d "{\"token\":\"test-token-string-1234567890\"}"
   # 期望：{"ok":true,"code":"1234","ttl":600}
   curl "https://你的域名/nxbox/get?code=1234"
   # 期望：{"ok":true,"token":"test-token-string-1234567890"}
   # 再查一次同一个码 → 应变成 {"ok":false,"msg":"取件码不存在或已被使用"}（一次性生效）
   ```

### 5. 把地址填进两个地方

| 位置 | 填什么 |
|---|---|
| 手表工程 `pages/index/index.js` 的 `CONFIG.BOX_API` | 上面那个地址（**结尾不带斜杠**） |
| 生成页面 `tools/box-web/index.html` 里的 `BOX_API` | 同一个地址 |

### 6. 托管「生成取件码」页面

任选其一：
- **uniCloud 前端网页托管**（推荐，同一控制台里就有）
- 任何静态托管 / 自己的服务器（纯静态单文件，无依赖）

把 `tools/box-web/index.html` 传上去，得到用户可访问的网址（例如 `https://你的域名/token.html`）。
**记得先改好里面的 `BOX_API` 再上传。**

### 7. 构建手表端

```bash
python tools/sync-to-h.py
# H 盘构建 + 签名（见 DEVELOPMENT.md 的构建配方）
```
构建前确认 `CONFIG.BOX_API` 已在 G 盘源码里填好（这样 H 盘构建区也会带上）。

## 二、用户怎么用（写进给用户的说明）

1. 手机或电脑浏览器打开**取件码页面**
2. 登录 `ws.fseatech.cn`（页面里有「复制书签代码」按钮，手机用户按教程存成书签取 Token）
3. 把 Token 粘进输入框 → 点**生成取件码** → 得到 **4 位数字**（10 分钟内有效）
4. 手表滑到「**我的**」→ 点底部「**取件码绑定**」→ 输入这 4 位数字 → 确认
5. 手表自动取回 Token 并绑定，「我的」页会显示 Token 剩余天数

## 三、安全设计（如实说明）

| 环节 | 措施 |
|---|---|
| 传输 | 全程 HTTPS |
| 存放 | Token 只存 **10 分钟**，取件成功即刻从数据库删除 |
| 一次性 | 同一个取件码取过一次即销毁，重复取返回「不存在或已被使用」 |
| 防爆破 | 4 位码（1 万组合）+ 10 分钟窗口 + **单码最多试 5 次**即作废 |
| 过期清理 | 每次调用顺手删除过期记录 |
| 与旧方案对比 | 比「私聊把 Token 发给作者」更规范：短时、可自取、不经过聊天记录 |

⚠️ 仍然需要注意：**Token 等于账号钥匙**，用户不要把 Token 或取件码转发、截图。

## 四、排错

| 现象 | 原因 / 处理 |
|---|---|
| 手表提示「取件功能未配置（缺 BOX_API）」 | 源码里 `CONFIG.BOX_API` 没填 → 填好重新构建 |
| 页面点生成报「页面还没配置服务器地址」 | `box-web/index.html` 里的 `BOX_API` 没改 |
| 页面报「网络失败」 | 检查 URL 化地址是否可访问；浏览器控制台看跨域错误 |
| 手表提示「取件码不存在或已被使用」 | 取件码已用过或输错；让用户重新生成 |
| 手表提示「取件码已过期」 | 超过 10 分钟，重新生成 |
| 手表提示「尝试次数过多」 | 同一码错 5 次后作废，重新生成 |
| 云函数报 `uniCloud is not defined` | 代码必须跑在 uniCloud 云函数里（不是普通 Node） |
